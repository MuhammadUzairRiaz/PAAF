How atom maps work
A map number tags one atom so PAAF can follow it through the reaction. Write it inside brackets after the element: [C:1]. The same number on both sides means the same atom.
worked example · esterification
acid
CC(=O)[OH:1]
alcohol
[C:2]CO
product
CC(=O)O[C:2]
Map 2 survives, so O bonds to it. Map 1 is absent from the product, so that OH leaves as water.
Three rules
1 · Map only the atoms whose bonds change.
2 · Every number must be unique per side.
3 · A number missing from the product is a leaving group — intentional or a mistake.

7 · Rules for the engineer
Layout mapping
Every row in these mockups is a QHBoxLayout, every column a QVBoxLayout. Fixed pixel widths (150 name, 66 maps, 24 remove, 340 right rail, 232 sidebar) are setFixedWidth; anything marked flexible is stretch 1.
Label/field pairs inside cards are QFormLayout with a right-aligned 84–96px label column. Cards are QGroupBox with a flat title bar drawn as a child widget, not the native title.
Tables are QTableView with verticalHeader().setDefaultSectionSize(28), alternating rows off, a 1px #F1F5F9 grid, sticky header at 26px, numeric columns right-aligned in the mono font.
The equation divider ("reacts to form") is a row of two QFrame.HLines around a centred label — cheap, and it keeps the reactant→product reading order in a narrow window without any absolute positioning.
SMILES fields need highlighting, so use a one-line QPlainTextEdit with a QSyntaxHighlighter for \[[^:\]]+:\d+\], not QLineEdit (which cannot carry rich text). Styled to look identical to the other inputs.
Behaviour & accessibility rules
State is never colour alone: every status carries a glyph (✓ ! ✕), a word, or a code (E-MAP-01). Error rows also get a left glyph in the index column and a border change.
Focus is a 2px #2563EB border with padding reduced 1px, plus a 1px #BFDBFE inner line on tables. Never remove the focus indicator; tab order follows visual order and the action bar is last.
Contrast: body #475569 on #FFFFFF is 7.5:1; #64748B captions are 4.8:1 and used at 11px minimum. Never place #94A3B8 on anything but white or #F8FAFC, and never for essential text.
Destructive actions (remove row, clear library) are outlined danger, never filled — a filled red button next to a filled blue primary is a misclick risk in a dense action bar.
One primary button per screen, always right-most in the 48px action bar, with the blocking condition stated in plain text to its left. Disabled primaries always have that explanation.
Validation runs only on explicit action; nothing is written to disk before it passes, and the status bar states so.
